# Керування конфігуратором дверей

Розділ тієї самої адмінки: **Конфігуратор дверей** (`/admin/door-configurator`). Доступ — лише адміністраторам.

## Щоденна робота

1. Виберіть «Двері» або «Ручки». Знайдіть товар за назвою/ID; для дверей є категорії й статуси.
2. Відкрийте модель. Назва, ціна та доступність походять із основного товару, не дублюються тут.
3. Відредагуйте матеріали: відтінок з каталогу, фото картки, полотно без ручки, опції скла/молдингу, кадрування й точку ручки. Координати фото нормалізовані до сітки 800 × 837; координати ручки — частки ширини/висоти 0–1.
4. **Зберегти чернетку** не змінює сайт. **Примірка UA / RU** відкриває збережену чернетку лише адміністратору; замовлення вимкнене.
5. Після перевірки натисніть **Опублікувати збережену версію**. Проблемні матеріали/прив’язки блокують публікацію з поясненням.

Нові відтінки спочатку вимкнені. Додайте матеріали й увімкніть потрібний відтінок перед публікацією. Порядок і видимість змінюються лише після публікації. «Приховати» прибирає модель тільки з конфігуратора, не з каталогу. Історія показує останні 30 редакцій; відновлення створює чернетку, старі фото зберігаються.

Для нової моделі знайдіть існуючий товар у блоці «Додати з каталогу». Прив’язка за ID залишається чинною після зміни slug. Кольори, додані до товару пізніше, не з’являються автоматично без підготовлених матеріалів. Ручки в сцені схематичні; фото використовується в картках, сумісність уточнюється окремо.

## Початковий імпорт і реліз

Джерела: `resources/data/door-configurator.json`, `door-configurator-interior.json` та підготовлені файли `public/assets/door-configurator/v1/`.

```sh
php artisan configurator:import
php artisan configurator:import --apply
```

Перша команда лише звіряє джерела та прив’язки, без запису. Друга копіює матеріали у постійне `storage/app/public/door-configurator/`, перевіряє варіанти й переводить публічний конфігуратор на БД. Непридатні варіанти залишаються вимкненими/чернетками з попередженнями. Немає жодної готової моделі — імпорт не активується.

Повторний імпорт **пропускає наявні моделі**, не перезаписує ручні правки й не додає до них нові відтінки. Нові відтінки існуючої моделі додавайте через редактор. Унікальні ключі й ID товарів захищають від дублів.

Реліз виконує міграції та `configurator:import --apply` до переключення `current`. Shared storage і `public/storage` зберігаються між релізами. Фото мають незмінні хеш-імена; завантаження перевіряється та перекодовується у WebP. Не видаляйте старі фото вручну — вони потрібні історії.

## Перевірка / відкат

- Перевірте UA/RU публічну сцену, перемикання дверей/кольорів/ручок і фото зі шляху `/storage/door-configurator/…`.
- Збережіть тестову чернетку й переконайтеся, що публічний вигляд не змінився. Примірка приватна; публікація — окрема дія.
- Кошик приймає тільки опубліковані варіанти й перераховує актуальні ціни на сервері.
- Для відкату одного матеріалу відновіть редакцію, перевірте примірку, опублікуйте. Для проблемної моделі доступне приховування.
- Відкат коду через попередній release не видаляє таблиці чи shared-файли. Старий код без підтримки адмінки знову читає власні JSON-пресети; ручні правки лишаються в БД для повернення на нову версію. Не відкочуйте міграцію з видаленням даних.

Початковий локальний імпорт: 184 моделі дверей та 3 ручки. Це готова частина, не весь каталог відтінків. Облік незавершеної підготовки: `docs/door-configurator-interior-status.md` і progress JSON.
